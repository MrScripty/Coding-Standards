# Milestone 5 Migration-Python Terminal Inventory

## Boundary

The canonical disposition authority is
`migration-python-dispositions.tsv`, which retired with its migration-only
subjects at M6-Z1 and remains available through repository history.
It covers migration-only Python modules and exposed check kinds plus the
launchers, integration hooks, tests, suites, live lifecycle records, generated
artifacts, and documentation that would otherwise preserve those interfaces.

This is a reviewed lifecycle inventory, not a repository scan or a permanent
component catalog. Mutable totals are derived from the table and current source.

## Inventory Method

The review used four complementary sources:

1. Python AST import inspection identified every caller of the candidate
   inventory, migration-graph, generated-artifact, numeric, and retained-checkpoint
   modules without interpreting comments or prose.
2. Strict parser and registry inspection identified the two exposed migration
   check kinds and their three registered lifecycle suites.
3. CLI, model, and engine inspection identified migration-only mixed-checkpoint
   phases, complete-catalog expansion, and path lookup symbols inside otherwise
   permanent modules.
4. Manual evidence and documentation review identified the live package,
   executable-edge, numeric, generated, test, and operator surfaces that must
   terminate with their owners.

No candidate has a current non-migration consumer after zero Bash. Tests and
historical imports do not authorize retention. Accepted ledgers and Git history
preserve execution history without keeping a live migration database.

## Binding Terminal Decisions

- The temporary inventory, graph, generated-artifact, numeric, retirement,
  executable-edge, and retained-checkpoint implementations are deleted at
  accepted zero-Bash closure.
- Their check kinds, parser branches, catalog exception, path lookup, launchers,
  suites, registry entries, dedicated tests, and live evidence are deleted in
  the same terminal slice. No wrapper or unknown-check alias remains.
- `verify.py --complete` is replaced in place by one Python-only all-suite
  checkpoint. The generated-artifact and retained-Bash phases are removed; an
  alternate compatibility mode is prohibited.
- The verifier README is retained only after temporary migration instructions
  are replaced with the final Python-only contract.
- The disposition table deletes itself after final acceptance records exact
  closure. It is migration control authority, not permanent engine metadata.

## Terminal Sequence

1. Continue checker retirement while this table and the existing lifecycle
   suites remain active.
2. Accept the final package only after the derived inventory reports no Bash
   verifier, helper, or migration launcher.
3. In one zero-Bash terminal slice, execute every triggered disposition,
   replace complete-mode semantics, and remove all imports, registrations,
   suites, tests, artifacts, and documentation named by deleted subjects.
4. Run source inspection for migration-only policy, all permanent Python tests,
   every remaining suite, generated freshness for permanent artifacts, and the
   Python-only complete checkpoint.
5. Record exact closure in final acceptance evidence, then delete the temporary
   disposition table and its validating migration suite.

If any named subject gains a real post-zero consumer before closure, or a new
migration-only Python surface is introduced, the table and terminal design must
be re-planned before the consumer or surface is accepted.
