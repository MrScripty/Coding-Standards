# Milestone 2 Route Acceptance

## Outcome

Milestone 2 is accepted. The Standards Engine now provides typed,
snapshot-bound `route`, `read`, `related`, and `inspect` operations through both
the native Python API and a schema-validating structured agent-tool facade.

## Router Projection

`STANDARDS-ROUTER.md` remains normative. The registered reviewed projection at
`evaluation/standards-effectiveness/router-projection.toml` supplies typed
executable applicability without redefining canonical module identities,
paths, `Requires`, or `Specializes`.

- Seven enum-set fact categories describe activities, workflow profiles,
  application forms, boundaries, languages, frameworks, and topics.
- Thirty-eight rules correspond exactly to the 38 unique canonical module
  targets linked by Router's selection tables.
- Structural validation rejects missing, extra, duplicate, unknown, malformed,
  or escaping projection state.
- The rule-to-condition translation is reviewed semantic projection. Target
  coverage and fixture outcomes are deterministic; no claim is made that code
  can infer English condition meaning.
- Missing contextual categories remain `unknown`, create typed questions, and
  retain unresolved candidate entries. They are never converted to false.

## Navigation

- Direct route selections come only from the registered projection.
- Required dependencies and deterministic ordering come from the existing
  `standards-requires` graph.
- Foundational authorities precede dependency-only and direct selections while
  preserving topological constraints.
- Route results can drive same-snapshot canonical reads without paths.
- The structured tool validates its request and result against the canonical
  schema and delegates all behavior to the native engine.
- The interface schema and Router projection participate in snapshot identity.
