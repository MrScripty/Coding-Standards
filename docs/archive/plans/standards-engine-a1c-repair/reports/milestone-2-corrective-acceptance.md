## Accepted Outcome

The corrective plan preserves the accepted A1c product architecture while
repairing its public-facade, immutable reconstruction, coverage invalidation,
evidence lifecycle, and acceptance-oracle boundaries.

Milestone 2 removes the one-time whole-graph migration verifier and its active
fixture, parser, tests, graph nodes, and three semantic relationships. The
completed relationship-migration table remains historical evidence only. It is
not a registered suite input, current graph consumer, or permanent comparison
against mutable policy authority.

The current A1c suite retains two proportional invariants:

- manifest-owned Python package roots and imports; and
- presence of current public Modules plus absence of retired authority wrappers.

The final graph contains 454 relationships. Regeneration derives 51 current
coverage requirements, and all 51 retain one exact authored attestation and
authorization record. The renewal changes requirement bindings only; reviewed
conclusions, evidence, exclusions, rationale, and auditor provenance remain
unchanged.

## Platform Evidence Split

The real Linux harness proves behavior that crosses the operating-system and
process boundary:

- Git-backed snapshot creation through the generated facade;
- SQLite close, unchanged closed-file copy, reopen, and concurrent cold reads;
- opaque snapshot, policy, analysis, and child-handle resolution;
- typed quarantine unavailability and undelete through public operations; and
- rejection of changed copied bytes before opening the consumer store.

The concurrent child result is now validated for its exact result kind and
content digest. A successful child process with unrelated output cannot satisfy
the claim.

Focused Snapshot tests separately prove deterministic transaction rollback,
aggregate publication, quarantine, expiry, purge, undelete, and cold-reopen
rules. Those tests are not represented as additional real-platform evidence.
Windows and macOS remain unsupported because no real environment evidence was
available.

## Closed-Store Hash Decision

The exact file hash has distinct, narrow value: it proves that the raw
administrative copy consumed by the harness is byte-for-byte the closed file
produced earlier. It is not snapshot identity, logical SQLite identity, a
public transfer operation, or a compatibility promise.

Retain this test-local check while the harness models transport with a raw file
copy. Remove it if the selected transport supplies equivalent integrity
verification or the harness stops copying raw closed-store bytes.
