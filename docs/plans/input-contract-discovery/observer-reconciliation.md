## Write set and design

- `codex_discovery_client.py`: shared-definition observation, exact runtime binding,
  actual call-start chronology and common fixture-outcome helpers.
- `replay_discovery_qualification.py`: read-only stock transcript replay and exclusive
  new verdict output; no Codex launch, Engine invocation or state migration.
- Qualification unit/integration tests and `INPUT-DISCOVERY-QUALIFICATION.md`.
- This record, the existing issues/ledger and the generated verifier input manifest.

Acquired definitions have one invocation-scoped owner. Names and canonical JSON
content are checked before admission; Python's boolean/numeric equality is not an
identity check. Discovery pages remain operation-qualified; common definitions do
not become operation-owned. A new catalog/instance/source/purpose cannot reuse the
previous record set. A definition received while an action is already running is
not evidence that the caller had it when constructing that action.

The same observer and fixture readback checks serve live and recorded evaluation.
Independent JSON Schema validation continues to own instance validity and variant
selection. No production cache, schema interpreter, registry, session pointer or
compatibility-removal switch is added.
