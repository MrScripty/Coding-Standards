# M6-I76 Rust Security Title Index Admission

## Decision

Admit one `shared-contract` package at train order 191 to replace
`evaluation/standards-effectiveness/verify-rust-security-title-index-closure.sh`
with an owner-local declarative suite and one generic Markdown section-scope
extension.

Fresh post-M6-I75 evidence reports 50 Bash verifiers, 53 nodes, 373 edges, and
53 components. No verifier has zero executable inbound references. The
Rust Security title-index checker is the highest dependency-wave caller. Its
single inbound reference is a historical string in the retained row-44 gate,
not an invocation. It executes eight independently owned retained gates and
contains a small direct Rust Security index contract.

## Preserved Contract

The suite preserves:

- the exact six source identifiers and their canonical Rust Security owner;
- one exact disposition per identifier, including the title's unique `index`
  disposition;
- title and introductory-route literals before the first child heading;
- case-insensitive rejection of mandatory, fallback, validator, limit, queue,
  listener, or runtime defaults inside that title body;
- separation from the generic Security index, which retains `STD-0582` and
  must not absorb `STD-0821`; and
- all eight retained gates as independent acceptance evidence rather than
  nested declarative execution dependencies.

The row-44 decomposition and retained gate transition their historical
verifier-name projection to the registered suite identity. The legacy source,
canonical Rust Security profile, and retained gate behavior do not change.

## Shared Assertion Boundary

Extend `markdown_section_text` with one explicit `scope` field:

- `subtree` retains the current default and selects the heading plus all
  descendants until a heading at the same or shallower level;
- `body` selects the heading and its body only, stopping at the next Markdown
  heading of any level.

Heading discovery remains fence-aware and exact. Unknown scope is typed
`invalid`; no regex, selector language, implicit level, policy branch,
alternate parser, or compatibility form is admitted. Focused tests must prove
the unchanged default, explicit subtree, heading-body cutoff, fenced heading
handling, strict configuration, and required/prohibited diagnostics.

## Acceptance Evidence

Acceptance requires direct assertion tests; one owner-local suite with exact
owner-map, disposition, title-body, generic-index separation, and lifecycle
checks; exact disposition of all sixteen outgoing executable/dependency edges;
row-44 consumer transition; at least four negative mutations; historical and
numeric lifecycle; final dependency-local coverage compilation; all verifier,
repository-Git, and graph tests; all registered suites; plan and generated
freshness; removal of the Bash checker; and the complete mixed checkpoint.

No Bash wrapper, duplicated source snapshot, weaker whole-file approximation,
retained nested execution, compatibility alias, waiver, or fallback is
admitted. The final write set and coverage renewal are frozen only after the
shared assertion, suite, and consumer transition compile together.
