# Milestone 7 Row 35 Root Index Decomposition

## Owner Contract

`STANDARDS-ROUTER.md` is the sole authority for selecting applicable workflows,
profiles, topics, dependencies, and exclusions. The root `README.md` is a
repository entrypoint and non-normative navigation surface. It cannot select a
module, define adoption procedure, preserve legacy policy, or act as fallback
authority when routing facts are unavailable.

Repository license terms are authoritative in `LICENSE`. Canonical standards
owners and non-normative references remain discoverable through the Router and
their own metadata or links; root-catalog presence is not owner evidence.

## Exact Ownership

- `STD-0001` indexes the legacy root parent to the Router-owned entrypoint.
- `STD-0002` splits routing from repository-adoption facts. Router owns module
  selection; adopting repositories own their contracts and exceptions.
- `STD-0003` indexes the manual document catalog to canonical Router evidence.
  Its `When to Use` policy and stale legacy descriptions are deleted.
- `STD-0004` becomes concise non-normative resource navigation. A template or
  recipe is not selected merely because it is linked.
- `STD-0005` indexes customization to Router-selected owners and adopting-
  repository contracts without a copied checklist.
- `STD-0006` indexes the summary to the repository's authoritative `LICENSE`.

Every identifier receives exactly one disposition. README may retain links,
but those links never establish applicability or canonical ownership.

## Typed Outcomes And No Fallback

Unknown applicability remains an unresolved Router diagnostic. Do not select
every module, use README presence as applicability, infer ownership from a
catalog row, preserve stale legacy descriptions, copy a customization
checklist, select a template by availability, paraphrase license terms, or
continue through a README fallback.

## Re-plan Triggers

Stop if implementation requires routing policy in README, a new canonical
module owner, generated catalog machinery, changes outside the frozen checker
or caller audits, multiple dispositions per identifier, preservation of the
manual `When to Use` catalog, or a third semantic child.
