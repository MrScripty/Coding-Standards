# Milestone 7 Row 36 Architecture Pattern Decomposition

## Owner Contract

`topics/architecture.md` remains the sole normative owner for concern
boundaries, responsibility placement, dependency direction, data and state
authority, and runtime composition. Applicable profiles and topics retain
their specialized lifecycle, projection, contract, persistence, concurrency,
security, resilience, and evidence authority.

`reference/patterns/architecture.md` is a non-normative adaptation aid. It may
illustrate a pattern only after canonical owners select the responsibilities,
boundaries, authority, lifecycle, contracts, and required evidence. Pattern
names, diagrams, role tables, directory shapes, data flows, and claimed
benefits cannot select policy or act as fallback when selection facts are
missing.

The owner contract is broad enough for the same proposed reference consumer in
rows 37, 39, and 40, but this decomposition authorizes movement only for row
36. Later composition, workflow, view-model, process-coordination,
discover-or-create, directory-template, and pattern-selection material retains
its immutable `owner-review` or package ordering and must be decomposed before
movement.

applicable canonical owners, but only the owner recorded in the validation

## Typed Outcomes And No Fallback

Missing ownership, boundary, lifecycle, source, consumer, synchronization,
reconciliation, or evidence facts remain the typed diagnostic selected by the
canonical owner. Do not select a fixed layer model, inward diagram, package
role catalog, backend owner, frontend prohibition, push flow, confirmed-only
projection, or incumbent pattern as fallback.

Legacy wording is removed or replaced when its child is accepted. It cannot
remain as a compatibility copy, advisory default, or alternate authority.

## Re-plan Triggers

Stop if implementation requires a normative rule in reference, a second
Architecture owner, a universal pattern recommendation, a new Frontend policy,
movement of row 37 or later identifiers, changes to immutable package
membership, more than four semantic children, multiple dispositions for one
identifier, or a P30 full-suite claim before row 37 is accepted.
