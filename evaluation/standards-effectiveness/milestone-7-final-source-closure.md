# Milestone 7 Final Source-Closure Decomposition

## Re-plan Finding

Milestone 7's exact rule migration bookkeeping is complete: all 916 frozen
identifiers have one disposition, the immutable execution train has no
remaining row, and the source-gap audit is empty. That evidence does not yet
prove source closure. The corpus still classifies 27 former standard or profile
entrypoints as normative. Fourteen are already concise indexes and thirteen
still contain expanded legacy material. Three concise sources also need a
wording rewrite before they can be accepted as pure navigation.

The Router separately retains two temporary legacy routes for
`CROSS-PLATFORM-STANDARDS.md` and `SECURITY-STANDARDS.md` using the condition
"until migration". Those routes contradict the completed identifier migration
and must be removed before any retained legacy entrypoint can be accepted.

Focused and complete validation exposed one shared-checker lifecycle defect in
two locations. The immutable execution-train verifier coupled its terminal
zero-remainder state to the mutable assertion that parent Milestone `7.4c`
remained `Planned`. The earlier trust/lifecycle re-plan verifier asserted that
same unrelated future state after proving its own accepted `7.4b4a` outcome.
Activating the approved closure child therefore failed after the owned evidence
had passed. The bounded correction gives the train verifier the stable accepted
handoff from `7.4b37b` to `7.4c1` and removes the unrelated forward assertion
from the trust/lifecycle verifier; neither checker owns later source-closure
status.

## Retention Decision

All 27 former stable entrypoints are retained only as concise, non-normative
migration indexes. This is justified by two frozen repository facts: each path
is a stable source represented in the original corpus, and each has an accepted
file-level owner-map disposition ending in `-and-index`. Retention preserves
navigation to one canonical owner; it does not preserve policy, defaults,
examples-as-authority, applicability decisions, or compatibility behavior.

If a source cannot be reduced to pure navigation without retaining competing
authority, its approved treatment is invalid. Execution must return a typed
re-plan outcome and reconsider deletion rather than preserve the legacy text.

## Source Treatments

The immutable source manifest records all 27 entrypoints in owner-dependency
order. Eleven already satisfy the expected index shape and require a focused
purity review (`retain-index`). Sixteen require replacement with a concise
canonical-owner index (`rewrite-index`), including the three currently concise
files whose wording still asserts policy. No source is pre-approved for
deletion because every source has the frozen stable-entrypoint and file-level
index evidence required by this decision.

Each source package has one observable outcome: the old file becomes derived
navigation to its named canonical owner, contains no normative rule, and no
longer appears as normative in the corpus. Source packages may be drafted in
isolation, but Router, corpus, shared inventories, plans, and ledgers remain
serial integration-owner files.

## Verification Gates

Every package requires source-specific index-purity checks, exact corpus state,
owner existence, link validity, metadata validity, no prohibited normative
language, shell syntax where applicable, staged-diff review, and diff
integrity. Because corpus classification and source authority are shared
contracts, every source package uses a complete-suite integration gate.

The Router slice additionally requires route inclusion and exclusion fixtures,
global proof that no legacy standard/profile route remains, and the complete
suite. Final closure requires all complete-suite verifier entrypoints, exact
916-disposition coverage, zero source gaps, zero normative standard/profile
corpus rows, no legacy Router route, generated-inventory agreement, and the
manual `D001` through `D010` review.

## Typed Outcomes And No Fallback

Missing owners, unresolved links, ambiguous applicability, prohibited legacy
policy, inconsistent generated state, or an unprovable retention decision are
typed invalid or unavailable outcomes. They cannot be converted into a copied
rule, dual authority, temporary legacy route, inferred owner, permissive index,
or compatibility shim.

## Re-plan Triggers

Re-plan before implementation when any of the following occurs:

- a manifest source or owner is missing;
- a source's accepted owner-map result does not end in `-and-index`;
- a retained source must carry normative content to remain useful;
- a package needs a canonical owner change or a write outside its boundary;
- Router cleanup removes a route still required by a canonical selection path;
- generated artifacts cannot be reproduced by their canonical generator;
- focused or complete verification exposes cross-owner semantic conflict; or
- the final `D001` through `D010` review finds competing authority.

There is no fallback to the frozen legacy source, old Router route, or a weaker
verification claim. A trigger pauses the affected package and records a bounded
replacement decision.
